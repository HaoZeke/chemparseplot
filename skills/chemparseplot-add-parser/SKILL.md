# Adding a chemparseplot parser

## Where it goes

- The module: `chemparseplot/parse/ENGINE/NAME.py` for a code that
  already has a directory (`eon`, `orca`, `sella`, `surrogate`,
  `trajectory`), or `chemparseplot/parse/NAME.py` next to `plumed.py`
  and `chemgp_hdf5.py`.
- The tests: `tests/parse/ENGINE/test_NAME.py`, or
  `tests/parse/test_NAME.py`. pytest collects `tests/` only; the
  layout in `docs/orgmode/dev/contributing.org`, with the test next to
  the parser, is not what the repository does.
- Re-exporting from the package `__init__.py` is optional:
  `chemparseplot.parse.orca` exports `geomscan` and the NEB parsers,
  most modules are imported by their full name.

## The module

[assets/scan_steps.py](assets/scan_steps.py) is a complete parser. It
reads the banner ORCA prints at each step of a bond scan and returns the
atom pair and the bond lengths:

- The SPDX header and a module docstring, like every file in the
  package.
- Only numpy, pint and the standard library at module level. The
  dependencies of chemparseplot are numpy and pint; `import
  chemparseplot.parse` loads `eon`, `orca` and `patterns`, and
  `chemparseplot.parse.orca` loads `geomscan` and `neb`, so a
  module-level import of anything else in a module they load breaks
  every bare install. Import optional packages inside the function that
  needs them (ruff's PLC0415 is switched off under
  `chemparseplot/parse/`). rgpycrumbs is not a dependency either: the
  `rgpycrumbs._aux.ensure_import` recipe in
  `docs/orgmode/dev/contributing.org` fails where rgpycrumbs is not
  installed.
- Values as pint quantities from `chemparseplot.units.Q_`, in the unit
  the code printed. Check it against the output instead of the code's
  defaults: `geomscan.extract_energy_data` labels ORCA scan distances
  bohr while ORCA printed ångström (see the `chemparseplot-orca-scan`
  skill). Unit names are pint's: `"hartree"`, `"eV"`, `"angstrom"`,
  `"bohr"`. `"kcal/mol"` is per mole in pint and does not convert from
  hartree; `"kcal_mol"`, which chemparseplot defines, does.
- A `ValueError` with a message when the text holds nothing to parse.
  `geomscan.extract_energy_data` returns empty arrays instead, and a
  misspelt table name then looks like an empty scan. Build messages in
  a variable first (`msg = ...; raise ValueError(msg)`); ruff's EM rules
  are on.
- A numpy-style docstring with a MyST block for the release that first
  ships the function:

  ````text
  ```{versionadded} 1.14.0
  ```
  ````

  The version comes from git tags (hatch-vcs); take the release after
  `git describe --tags --abbrev=0`. The API reference at
  `/apidocs/` is generated by sphinx-autodoc2 from every module of the
  package, so the docstring is the reference page and there is nothing
  to register.

## Tests

[assets/test_scan_steps.py](assets/test_scan_steps.py) shows the usual
shape: a snippet of real output inline, the error paths, and a check
against a whole run when one is in the repository.

- Mark the module `pytestmark = pytest.mark.pure` when the parser needs
  only numpy and pint. pyproject.toml declares three markers: `pure`,
  `neb` (ase, polars, h5py, scipy, matplotlib and rgpycrumbs; add
  `skip_if_not_env("neb")` from `tests.conftest`, as
  `tests/parse/test_neb_utils.py` does) and `grammar` (parsimonious).
  The `plot` marker that `docs/orgmode/dev/contributing.org` lists is not
  declared.
- Keep snippets inline or in `tests/fixtures/`. A whole output goes in
  gzipped, like `doc/source/tutorials/orca/data/scanuhf.gz`; the
  pre-commit hooks refuse files over 1000 kB.
- Run one file with `uv run pytest tests/parse/orca/test_scan_steps.py`.
  CI runs `uv sync --all-extras` and `uv run pytest --cov=chemparseplot
  tests` on Python 3.11 and 3.12. `uv run` and `uv sync` may rewrite
  `uv.lock`; leave that out of the commit unless the dependencies
  changed.

## Lint, changelog and docs

- `uv run ruff check` and `uv run ruff format` on the new files, or
  `uvx prek run --files FILE...` for all the hooks of `prek.toml`
  (ruff, ruff-format, taplo, codespell, whitespace).
- A towncrier fragment in `doc/release/upcoming_changes/`. A release
  moves the fragments into `CHANGELOG.md`, so on main the directory may
  not exist until the first fragment is added:
  `ISSUE.added.md`, or `+NAME.added.md` without an issue. One line or
  paragraph of Markdown. The types are `removed`, `deprecated`, `added`,
  `changed`, `fixed` and `misc`. Preview with `uv run towncrier build
  --draft --version X.Y.Z`; the draft changes nothing.
- A how-to page when the parser is meant for users:
  `docs/orgmode/howto/NAME.org`, added to the How-to toctree in the
  `#+begin_export rst` block of `docs/orgmode/index.org` and to the
  table in `docs/orgmode/howto/index.org`, plus a line in the site map
  `doc/source/llms.txt`. Then run `python scripts/llms/build_llms.py`;
  CI fails while `llms-full.txt` is stale.
- Commit subjects follow the log: `feat(parse): read ORCA scan step
  banners`.

## Check

```bash
python scripts/scaffold_check.py
```

copies the package, the tests, `pyproject.toml`, `CHANGELOG.md` and the
ORCA tutorial run into a temporary directory, puts the two assets at
`chemparseplot/parse/orca/scan_steps.py` and
`tests/parse/orca/test_scan_steps.py`, and checks that Python imports
the module from the copy, that its four tests pass, that ruff check and
ruff format accept both files under the repository's rules, and that a
fragment shows up under "Added" in a towncrier draft. The checkout is
not changed.
